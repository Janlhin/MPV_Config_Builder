### ⚠ 为什么 i18n 机制（1）要排在界面打磨（2）前面

直觉上会想「先把界面做好看，再弄多语言」。**但那样会返工一遍**：
先把快捷键、右键菜单、状态栏都用中文写死，等做 i18n 时那些新文字**又得再抽一遍**。

正确顺序是**先搭机制、再打磨** —— 新功能一开始就按 i18n 的规矩写，一步到位。

注意第 1 步**只搭机制**（框架 + 切换 + 一个页面当样板），不是把 1098 处翻完；
翻完是第 3 步。

|---|---|
| README 的语气重写（少 AI 味） | **等用户发参照文字**（一两段他觉得有味的），不然猜不准 |
| 界面里 4 份文档的翻译 | 用户原话：「最后做文档翻译吧」 |

### 战略级待办：换语言从零重写（T17，2026-10-14 用户提出）

**是什么**：可能用 Go / Rust / C++ / C# 等某个语言重写整个软件，并**完全从零开始构建 i18n**。已立为 T17；结论（做 / 不做 / 缓）出来前不动代码，结论落 `DECISIONS.md`。

**动机（记下来，免得评估时忘了为什么）**：

1. **i18n 从零**。现在这套是后补的——词典兜底 + `data-i18n` + 后端字符串转 T14，`踩过的坑.md` 里界面类条目近一半是 retrofit 的税（半句规则、动态内容盖不到、后端串被通用词条误切）。从零构建能把 i18n 做成一等公民而不是补丁。
2. **分发**。现在要么装 Python（右键 `启动.ps1` 运行），要么 PyInstaller 打包 exe——未签名还要向用户交代 SmartScreen（顺序表第 9 项）。Go / Rust 单二进制静态链接没有这个问题；C# 可 self-contained 但体积大。
3. **"套壳感"的终极形态**：原生窗口、原生控件。

**反对意见（同样要记，评估时逐条回应）**：

1. **旧裁定只覆盖了外壳**。2026-09-14 否决过「换掉 Electron 界面技术（Qt / Tauri / C#）」，理由是套壳感来自缺快捷键/右键/状态栏这些细节——那个结论对「只换外壳」仍成立，但**不能引用它给全栈重写结案**，两者不是同一个问题（详见 §五 该条的补注）。
2. **成本是全量的**。701 项测试、9 个页面、`core/` 全部逻辑、围绕 Python + Electron 建起的门禁与文档体系（AGENTS.md / DECISIONS.md / 本文件 / verify.py）都要重建或重验；而 i18n 刚做完 5 页做深，债务只剩 keys 一页加 T14——现在重写，恰好把刚还清的那部分债重新借一遍。
3. **收益真实性存疑**。核心逻辑（写 mpv.conf / 扫目录 / 融合 vpy / 下载校验）与语言无关，重写不改善正确性；分发问题用打包已实质缓解（`verify.py packaged` 13/13 绿）；启动速度对本机工具不敏感。

**评估时必须回答的问题**（构成 T17 的动作清单，缺一条不产出结论）：

- 候选语言按上面的动机/反对意见逐项实测对比，而不是凭印象排优先级；
- 迁移成本账要落到「哪些测试/检查/文档可以平移，哪些必须重写」；
- 「从零 i18n」的落地形态：运行时语言包（等价于现在机制的正装版）还是编译期注入，两种各自的代价；
- 如果结论是「缓」：缓到哪个里程碑之后（例如 1.0.0 发布且 T14 清零之后）再重评。

## 三、已定的约定（不是待做，是规矩）

### 版本号怎么涨

**唯一来源是 `core/schema.py` 的 `VERSION`。** 改完跑 `py tools/build.py version`
把版本刷进 `electron/package.json`（那边打包时要用）。忘了跑也没事 ——
`tests/test_version.py` 有一条测试钉住两边相等，会红。

| 什么时候 | 怎么涨 | 例 |
|---|---|---|
| 小更新（改文案、修 bug） | 最后一位 | 0.1.0 → 0.1.1 → 0.1.2 |
| 大更新（加功能） | 中间那位 | 0.1.x → 0.2.0 |
| 觉得能正式推荐给别人了 | 第一位 | 0.x → 1.0.0 |

所以 **0.x 阶段就是「还在做」的意思**。

> 2026-09-14 顺带定：**界面只显示软件版本**，不再显示「2.0」。
> `APP_VERSION = "2.0"` 那个常数留着，但只为旧界面服务 —— 那份 2026-10-09
> 已移出仓库、归档到 `..\MPV_Config_Builder_legacy\`，而它 import 的是**仓库里的**
> `core.schema`，所以这个常数**不许删**（`tests/test_version.py` 钉着）。
> 主界面测试会拦着不让它用。生成的配置抬头也从
> `# MPV Config Builder 2.0` 变成了 `# MPV Config Builder`。
> 合并写入不受影响 —— 它认的是另一条标记「由 MPV Config Builder 写入」。

### 界面里不许直接 fetch `/api/`

传输是可替换的（HTTP / stdio）。页面里任何一处直接 `fetch('/api/...')`
都会在 Electron 下静默失效。全部走 `API.xxx()`。
由 `tests/test_frontend_transport.py` 静态守着。

## 四、已拍板的决定（2026-09-14）

下面每条都附了当时的理由 —— 记着是为了**下次别又问一遍**。

### 1. 给谁用 → **发出去给别人用**

⚠ 这条把优先级全改了。「自己用」时可以不管的事，现在都变必须：
README 中英双版、界面文案排查、后端挂了要有提示、未签名的交代、英文界面。

### 2. 原版 mpv → **做成同等支持**

改三处：README 定位（"原版也能用，mpv-lazy 用户更方便"）、自动探测的说明、
组合预设里标出哪些依赖 mpv-lazy 的 shader 包（原版用户选了会是空的）。

### 3. 初始化引导 → **只在第一次出现**

进去后就不再问；想要时能从菜单里手动打开。
内容：先问「你要干嘛」（从零开始 / 改现有配置 / 只看体检）→ 再展示检测到的
多个 mpv 目录让你确认。

> 现在会**挑一个就停，从不告诉你还有别的** —— 用户机器上
> `C:\Program Files\mpv-lazy\portable_config` 和 `%APPDATA%\mpv` 都存在，
> 但程序只用了第一个，界面上不说。

### 4. README → **合并成中英双版，只留简介**

英文当默认（`README.md`），中文放 `README.zh-CN.md`。
`README.txt` 删掉，里面的目录结构、打包步骤等详细内容进 `docs\`。

### 5. shader 扫描 → **改成列表，不做全盘扫**

用户确认 shader 都在标准的 `portable_config\shaders\` 和 `vs\` 下。所以：
- 要做「扫描源改成列表」（自动探测 + 手动添加多个目录）
- **不必做**「读 mpv.conf 看实际引用路径」（他的都在标准位置）
- **不做全盘扫**（慢、会扫到无关的、且 mpv 未必加载得了）

### 6. 代码签名 → **不买**

不是"什么都不做"，而是要给未签名的安装包一套交代（见顺序表第 9 步）：

| 要做 | 为什么 |
|---|---|
| README 写清会看到什么、怎么继续 | 不写的话用户以为是病毒 |
| 配那个对话框的截图 | 光用文字描述，用户对不上号 |
| 发布 SHA256 校验值 | 未签名时唯一能验证"没被换包"的手段 |
| 提醒国产杀软可能报毒 | 未签名的打包 exe 在国内比 SmartScreen 更常见 |
| 从 GitHub Releases 发布 | 别放网盘 —— 更容易被换包 |

⚠ 打包时**不要开 UPX**（杀软误报率显著提高），配方里已经关掉了。

### 7. 英文界面 → **一定做**

用户原话：「英文界面一定做，README 也做」。

**中文是默认**（用户母语），英文加上，界面上有个地方能切。

实测工作量：

| 部分 | 条数 |
|---|---|
| 界面文字（HTML + JS） | 约 1098 条 |
| 后端文案（Python） | 149 条 |
| 选项说明 | **726 条**（平均 140 字，共约 10 万字） |
| 分类名 | 24 个 |

**⚠ 选项说明那块不用翻译**：那 726 条中文是从 mpv 官方 `options.rst` 翻过去的，
直接取官方英文原文即可 —— 比翻译准，也比翻译省事。来源跟中文那份对称
（中文来自 `mpv_doc-CN`，英文来自 mpv 官方手册）。

**i18n 用「抽成 JSON + 运行时切换」，不做两套 HTML。**
两套 HTML 意味着 9 个页面变 18 个、改一处要改两遍 —— 就是本项目一直在避免的"存两份"。

### 8. 英文界面下的 4 份中文文档 → **最后再翻**

在那之前：切到英文时文档页照常显示中文，**顶部提示一句**
「这几份文档目前只有中文」。不装作有英文版，也不隐藏。

## 五、明确不做

| 不做 | 原因 |
|---|---|
| 换掉 Electron 界面技术（Qt / Tauri / C#） | 讨论过。Qt 更"原生"但要重写 9 个页面，而且**用户介意的"套壳感"其实来自缺快捷键/右键/状态栏这些细节，换技术也躲不掉**。**（2026-10-14 补注：该条只否决「只换外壳」；连 `core/` 一起的全栈重写是未决战略项，见 §〇 末与 T17，不要引用本条给它结案）** |
| 给 Tkinter 版打包 | 旧界面 2026-10-09 已移出仓库、本地归档（仓外副本自带 `自检.py`，不为其维护打包配方） |
| macOS / Linux 版 | 目标平台是 Windows |
| 自动更新 | 没配更新服务器 |
| 买代码签名证书 | 已决定不买，改用文档兜（见上面第 6 条） |
| 全盘扫描 shader | 慢、会扫到无关文件，且 mpv 未必加载得了（见第 5 条） |
