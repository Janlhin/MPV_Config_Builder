## 一、待做（已确定要做，只是没做）

### 1. Electron 界面「像个正经软件」那批

现状：**能用，但有明显的"套壳感"**。缺的都是桌面软件的常规配置。

| 缺什么 | 现状 | 影响 |
|---|---|---|
| **键盘快捷键系统** | 基本全靠鼠标 | 改一个选项要点半天 |
| **右键菜单** | 没有 | 想「恢复默认 / 复制选项名 / 看手册原文」无从下手 |
| **底部状态栏** | 没有 | 看不到当前配置文件路径、改动几处、后端是否活着 |
| **后端挂了有提示** | **白屏，什么都不说** | 用户以为软件坏了 |
| **加载中的进度** | 有些地方直接空白 | 读配置、扫描 shader 目录时像卡死 |
| **自绘标题栏** | 系统默认灰条 | 一个改动就能让"套壳感"少一半 |

> 用户原话：「快捷键 配置体检这种体验不是很好」—— 指的就是这批。
> 不是这两个功能做得差，是它们**不像"软件的一部分"**。

### 2. 界面文案排查

已发现一条错的：界面里写着「下载与一键安装目前只在旧版界面」，
但网页版早就有下载中心和一键安装了（R-8w 做的）。

**全代码里到底还有多少条过期的，没有排查过。**
文案是写死在 HTML 里的，改功能时容易忘了改它。

### 3. 功能上的缺口

| 项 | 说明 |
|---|---|
| **本地 HTTP 的 Origin 校验** | 现在浏览器里别的网页能打你本机的服务端口。stdio 模式没这问题，网页版有 |
| **英文版** | 现在全中文。要做 i18n 层 + 英文选项说明（得从 mpv 的 `DOCS/man/options.rst` 取，`--list-options` 里没有描述） |
| **VS 插件一键安装** | 往 VapourSynth 目录装插件。风险较高（写到 mpv 配置目录外面） |
| **`prefers-reduced-motion` 适配** | 无障碍缺口。小活，**不管加不加动效都该补** |
| **界面动效** | 要不要加、加哪些 —— 一直没拍板 |

### 4. 发布前要给未签名安装包做的交代

**已决定不买代码签名证书**（见「三之三」第 9 条）。所以这一项不是"买证书"，
而是**把警告讲清楚，让陌生人不会被吓跑**：

| 要做的 | 在哪做 |
|---|---|
| 写清 Windows 会弹什么、怎么继续（「更多信息 → 仍要运行」） | README |
| 配一张那个对话框的截图 | README |
| 发布 SHA256 校验值 | GitHub Release 说明 |
| 提醒国产杀软可能报毒（未签名打包 exe 常见） | README |

⚠ 打包时**不要开 UPX**（杀软误报率显著提高），配方里已经关掉了。

## 三之二、已定的规则（不是待做，是约定）

### 版本号怎么涨

**唯一来源是 `core/schema.py` 的 `VERSION`。** 改完跑 `py tools/sync_version.py`
把版本刷进 `electron/package.json`（那边打包时要用）。忘了跑也没事 ——
`tests/test_version.py` 有一条测试钉住两边相等，会红。

| 什么时候 | 怎么涨 | 例 |
|---|---|---|
| 小更新（改文案、修 bug） | 最后一位 | 0.1.0 → 0.1.1 → 0.1.2 |
| 大更新（加功能） | 中间那位 | 0.1.x → 0.2.0 |
| 觉得能正式推荐给别人了 | 第一位 | 0.x → 1.0.0 |

所以 **0.x 阶段就是「还在做」的意思**。

> 2026-09-14 顺带定：**界面只显示软件版本**，不再显示「2.0」。
> `APP_VERSION = "2.0"` 那个常数留着，但只为 `legacy/` 那个旧界面服务
> （主界面测试会拦着不让用它）。生成的配置抬头也从
> `# MPV Config Builder 2.0` 变成了 `# MPV Config Builder`。
> 合并写入不受影响 —— 它认的是另一条标记「由 MPV Config Builder 写入」。

## 三之三、已拍板的决定（2026-09-14）

上面那 7 条待定，全部定完了。记在这里，免得下次又问一遍。

### 1. 这软件给谁用 → **发出去给别人用**

⚠ **这条把优先级全改了。**「自己用」时可以不管的事，现在都变必须：

| 原来可以不做 | 现在 |
|---|---|
| README 写得随意 | 必须中英双版，陌生人看得懂 |
| 界面文案过期 | 必须排查 |
| 后端挂了白屏 | 必须有提示 —— 用户机器上出错概率更高 |
| 没代码签名 | SmartScreen 会拦，陌生人到这一步就走了 |
| 英文版界面 | 现在全中文，老外下载了看不懂（**新问题**） |

### 2. `legacy\` 那套 Tkinter → **本地移出归档，仓库里删掉**

归档到仓库**旁边**（比如 `..\MPV_Config_Builder_legacy\`），保持能跑。
GitHub 历史里也有，实在找不到可以用 `git show` 取。

### 3. 原版 mpv → **做成同等支持**

改三处：README 定位（"原版也能用，mpv-lazy 用户更方便"）、自动探测的说明、
组合预设里标出哪些依赖 mpv-lazy 的 shader 包（原版用户选了会是空的）。

### 4. 初始化引导 → **只在第一次出现**

进去后就不再问；想要时能从菜单里手动打开。
内容：先问「你要干嘛」（从零开始 / 改现有配置 / 只看体检）→ 再展示检测到的
多个 mpv 目录让你确认（现在会挑一个就停，**从不告诉你还有别的**）。

### 5. `产品规划与路线图.md` → **拆，并把开发记录里有用的抽出来**

实测 1109 行里，真正给用户看的只有 §一 + §二（约 123 行）。
⚠ 那 17 条冲突规则「依据哪句 mpv 手册原文」**只记在这份文件里**，
代码注释里没有 —— 拆的时候必须先抽出来。

### 6. README → **合并：只留简介，详细进 `docs\`**

中英双版（英文当默认，中文 `README.zh-CN.md`）。
`README.txt` 删掉，里面的目录结构、打包步骤等详细内容进 `docs\`。

### 7. `tools\` → **合并成 3~4 个**

17 个文件、3000+ 行 → `verify.py`（验证）/ `build.py`（构建）/ `uidriver.py`（公共库）。

### 8. shader 扫描（补充决定）

用户确认：**shader 都在标准的 `portable_config\shaders\` 和 `vs\` 下**。
所以：
- 「扫描源改成列表」要做（自动探测 + 手动添加多个目录）
- 「读 mpv.conf 看实际引用路径」**不必做**（他的都在标准位置）
- **不能做全盘扫**（慢、会扫到无关的、且 mpv 未必加载得了）

### 9. 代码签名 → **不买**

2026-09-14 用户决定。所以安装包是**未签名**的，陌生人下载会遇到警告。

**这条决定带来一串必须做的事**（不做的话别人下载完就走）：

| 要做 | 为什么 |
|---|---|
| **README 里写清楚会看到什么** | 告诉用户 Windows 会弹「已保护你的电脑」/ SmartScreen 蓝框，要点「更多信息」→「仍要运行」。**不写的话用户以为是病毒** |
| **最好配一张那个对话框的截图** | 光用文字描述，用户对不上号 |
| **发布 SHA256 校验值** | 未签名时这是唯一能让用户确认"没被篡改"的手段 |
| **提醒国产杀软可能报毒** | 未签名的打包 exe 在国内经常被 360 / 火绒拦。这个比 SmartScreen 更常见 |
| **从 GitHub Releases 发布** | 别放网盘 —— 网盘链接更容易被人换包 |

⚠ **不建议**用 UPX 压缩（杀软误报率显著提高），打包配方里已经关掉了。
