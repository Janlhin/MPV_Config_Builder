## 一、高危（8 条）

### 1. 全项目没有原子写，所有落盘都是就地覆写
- **位置**：`core/writer.py:413`（同型：`core/textio.py:188`、`writer.py:212/214/230/232`、`dlcenter.py:414`、`presetfile.py:280`、`keys.py:332/389`、`vpy.py:340`、`schema.py:58`）
- **问题**：`write_bytes` 直接截断目标文件再写，没有 tmp + `os.replace`；`grep -E "os.replace|os.rename|mkstemp|NamedTemporaryFile" core webui tools` **零命中**。
- **证据**：
  ```python
  p.write_bytes(textio.encode(body, encoding, bom))
  ```
- **影响**：写一半崩溃/断电/被强杀 → `mpv.conf` 变半截。备份文件在，但原文件已毁——"写前一定备份"这个卖点在最需要它的场景失效。
- **建议**：`textio` 增 `write_atomic()`（同目录 tempfile → fsync → `os.replace`），让 `writer.write_lines / write_include / ensure_include_line` 与 preset/manifest 全部走它。

### 2. 写入白名单可以被请求体自己撑开（任意路径任意写）
- **位置**：`webui/server.py:575-591`（调用点 `603`、`624`、`1160`），配合 `1261-1270`
- **问题**：`_allowed_write_roots([body.get("target")])` 把客户端传来的字符串直接当白名单根；`do_POST` 不看 `Origin`/`Referer`/`Content-Type`。
- **证据**：
  ```python
  for body in extra:
      if body:
          roots.append(body)
  ```
- **影响**：任意网页用 `text/plain` 简单请求（不触发预检）即可 POST `{"path":"C:\\...\\x.bat","text":"...","target":"C:\\"}` → 任意文件写入（CSRF）。`docs/待做.md` 已承认缺 Origin 校验，但**白名单自毁这一条文档里没提**。另：`_apply_config`/`_basic_apply` 走 `_resolve_target`，完全不过白名单，受攻击面更大。
- **建议**：白名单只由服务端状态计算（已保存 target + 安装目录），永不接受 body 里新增的根；加 `Origin` 校验，并要求 `Content-Type: application/json`。

### 3. include 行判定是全文子串匹配，会静默不生效
- **位置**：`core/writer.py:223`
- **问题**：只要文本里出现过 `mpv-builder.conf` 就认为"已有 include 行"，注释行、别的 profile 里的引用都会命中。
- **证据**：
  ```python
  if INCLUDE_FILENAME in text:
      return False, None, "主配置里已有 include 行，未改动"
  ```
- **影响**：用户配置里有 `# include = "~~/mpv-builder.conf"`（手工注释掉）时，接口返回 `ok: true`「已写入 mpv-builder.conf，主配置里已有 include 行」，而配置**永远不生效**。
- **建议**：改成解析后判断——只认全局区的 `include`/`include-append` 且值规范化后等于 `~~/mpv-builder.conf`。

### 4. 同名键出现多次时只改第一处，改动被 mpv 忽略
- **位置**：`core/writer.py:269-291`
- **问题**：`find()` 命中第一处就返回，后续同名启用行原样留着；mpv 以**最后一次**为准。
- **证据**：
  ```python
  def find(key, active):
      for i, ln in enumerate(out):
          ...
          return i, m
  ```
- **影响**：读侧 `parse_config_text` 用 dict（最后一次生效）显示的是第 2 个值，写侧改的是第 1 个 → 界面显示"已合并 1 处改动"，播放行为不变。而 `comment_keys_in_lines:343-351` 会把**全部**匹配行注释掉，两条路径不一致。
- **建议**：写入时收集全部同名启用行，统一改写（或最后一处写新值、其余注释），并给出"修正了 N 处重复"的说明。

### 5. 断点续传不校验 `206`/`Content-Range`，会把整包追加到残留片段后
- **位置**：`core/installer.py:250-274`（关键 255-263）
- **问题**：只要本地有残留就发 `Range`，但不管服务器是否真的按 Range 返回；镜像站/CDN 忽略 Range 返回 200 全文时，直接 `mode="ab"` 追加。
- **证据**：
  ```python
  start = dest.stat().st_size if (resume and dest.exists()) else 0
  mode = "ab" if start else "wb"
  ```
- **影响**：包体前段重复、后段错位 → 损坏；而 `dlcenter.CATALOG` 多数条目 sha256 为空，"未校验"分支会照印"已安装"，用户拿到坏脚本/坏字体。
- **建议**：检查 `resp.status == 206` 且 `Content-Range` 起点等于 `start`，否则 `start=0, mode="wb"` 重下；`.part` 续传前记录 `ETag`/总长做一致性校验。

### 6. 基础模式 target 为空 → 写进进程当前目录
- **位置**：`webui/server.py:196`、`236-237`、`278-280`
- **问题**：`Path("")` 在 Windows 上等于 `Path(".")`，`target.is_dir()` 恒为真，于是"目标目录不存在"的守卫失效。
- **证据**：
  ```python
  target = Path(str(body.get("target", "")).strip())
  ...
  if not target.is_dir():
      return {"ok": False, ...}
  ```
- **影响**：未探测到 mpv 时点"应用"，会在进程 CWD（Electron 的 `cwd` 是 `webui/` 目录，见 `main.js:120`）生成 `mpv.conf` + `mpv-builder.conf`，用户以为什么都没发生。
- **建议**：空串直接报错，或统一走 `_resolve_target()`（它至少会回退到 `find_lazy_pc()` 并校验）。

### 7. 安装清单非原子写、写失败被忽略、损坏即静默清空
- **位置**：`core/dlcenter.py:399-417`（`load_manifest` 399-408、`save_manifest` 410-417、`record_install` 420-444）、调用点 `580`/`638`
- **问题**：`save_manifest` 直接 `write_text`；失败只 `return False`，`record_install(...)` 的返回值调用方从不检查；`load_manifest` 遇 `OSError/ValueError` 直接返回空清单。
- **证据**：
  ```python
  p.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")
  ```
- **影响**：文件装好了但没记录 → 卸载入口消失、`list_items` 全部变 `present_untracked`；清单被写坏一次，所有历史安装记录**无声消失**。
- **建议**：原子写 + 写后回读校验；`record_install` 失败要让安装结果带 `warning`；解析失败时保留原文件并报 `broken`。

### 8. Electron 退出时"先礼后兵"实际是立即强杀
- **位置**：`electron/main.js:197-208`
- **问题**：设了 1500ms 定时器，但紧接着无条件 `p.kill()`。
- **证据**：
  ```js
  const t = setTimeout(() => { try { p.kill(); } catch (e) {} }, 1500);
  p.on('exit', () => clearTimeout(t));
  try { p.kill(); } catch (e) { /* 已经没了 */ }
  ```
- **影响**：Windows 上 `kill()` 是 `TerminateProcess`，后端没有任何清理/落盘机会；与发现 1 叠加，就是"关窗口时正在写 mpv.conf"→ 文件损坏的真实路径。
- **建议**：删掉最后那行 `p.kill()`（只保留定时器），并给后端加 SIGTERM/EOF 时的短超时优雅退出；`this.dead` 也应在重启时复位。

## 二、中（8 条）

### 9. 一键安装 `copytree` 失败留半个 `portable_config`，且下次直接拒绝
- **位置**：`core/installer.py:640-649`（`521-523` 是"已存在"守卫）
- **问题**：没有"先复制到临时目录再 rename"的步骤，失败后不回滚也不清理，第二次运行被"已经有 portable_config 了，不覆盖"永久挡住。
- **影响**：用户得到一个装了一半、卸载不掉、也重装不了的目录（GB 级），提示还没告诉他该删哪个。
- **建议**：`copytree` 到 `dest + ".part"` 成功后 `os.replace`；失败明确提示可重试或给出需删除的路径。

### 10. 覆盖安装时 `shutil.move` 在 Windows 上退化为 `copy2`（非原子）
- **位置**：`core/dlcenter.py:623-626`
- **问题**：目标已存在时 `os.rename` 在 Windows 抛 `OSError`，`shutil.move` 走 `copy2 + unlink`；这里只备份、不删除，所以必然走这条路。
- **影响**：覆盖瞬间目标文件处于"已截断、正在写"状态；中途失败得到半截 `.lua`/`.ttf`，`.part` 已被 unlink，连重试原料都没了。
- **建议**：改为 `os.replace(tmp, dest)`（同卷原子覆盖），备份保留。

### 11. archive 安装逐文件 move，勾选覆盖后没有回滚点
- **位置**：`core/dlcenter.py:360-386`
- **问题**：`overwrite=True` 时跳过整批冲突预检，随后逐文件 `shutil.move`；第 N 个失败时前 N-1 个已生效，且此时还没 `record_install`。
- **影响**：`fonts/` + `scripts/uosc/` 半新半旧且无记录，卸载器完全看不到这批文件。
- **建议**：整批移到 `base/.mb-staging-<ts>/`，全部成功后逐个 `os.replace`；失败回滚已替换项。

### 12. 同一 item 连点两次 → 两个线程写同一个临时文件
- **位置**：`core/dlcenter.py:592`、`core/installer.py:549`
- **问题**：`.part` 路径是确定值、`_install_stage` 是共享目录；`api_download_start` 每次点都起新线程，没有 per-item 互斥。
- **影响**：两条流交错写同一文件 → 内容损坏；进度回调互相覆盖；`run_install` 互相删对方的分卷。
- **建议**：加 `_RUNNING = {item_id: job_id}`，同 key 复用现有 job；临时文件名带 job id。

### 13. zip 成员只拦 `/` 与 `..`，不拦盘符
- **位置**：`core/dlcenter.py:257`
- **问题**：`rel` 形如 `C:/Windows/x.dll` 时既不以 `/` 开头也不含 `..`，随后 `stage/"x"/rel` 与 `base/rel` 在 Windows 上被解释成**绝对路径**。
- **影响**：`base / rel` 可落到磁盘任意位置（当前只有 uosc 走 archive，且被 `keep` 白名单挡着，这是唯一一道防线）。
- **建议**：改用 `Path(rel).is_absolute() or Path(rel).drive` 判断，最后统一 `os.path.commonpath` 复核。

### 14. 编码编不出来时静默整篇转 UTF-8，但提示说"按原编码写回"
- **位置**：`core/textio.py:155-159`（调用点 `writer.py:212`、`server.py:526-527/639-640`）
- **问题**：`encode()` 捕获 `UnicodeEncodeError` 后整体 `text.encode("utf-8")`，调用方毫不知情。
- **证据**：
  ```python
  except (UnicodeEncodeError, LookupError):
      return text.encode("utf-8")
  ```
- **影响**：GBK/Big5 配置里新增 emoji → 整份文件变 UTF-8（原 GBK 中文在新编码下对用户编辑器变乱码），而界面明确写"文件按原编码 GBK / GB18030 写回"——**提示与实际相反**。
- **建议**：`encode()` 返回 `(bytes, actual_encoding)` 或新增 `encode_report`，上层明确告知；至少把回退写进 detail。

### 15. GET 接口带写副作用；settings.json 非原子、无锁、路径在 import 期固化
- **位置**：`webui/server.py:374-396`（`_resolve_target` → `_remember_target`）、`core/schema.py:45`
- **问题**：`/api/catalog`、`/api/keys`、`/api/downloads`、`/api/backups` 这些 GET 都会走到 `_remember_target()` 写 `settings.json`；`ThreadingHTTPServer` 多线程无锁；`SETTINGS_PATH` 在导入时求值，`set_user_data_dir()` 之后不生效。
- **影响**：一次只读请求就可能改写用户设置；并发点击时两份 JSON 交错写坏；测试/工具里覆盖用户目录对它无效（"看起来隔离了其实没隔离"）。
- **建议**：`_remember_target` 只在显式设置目标（POST）时调用；`SETTINGS_PATH` 改成函数；写 settings 加锁 + 原子写。

### 16. `Content-Length` 未校验、无上限、无 socket 超时
- **位置**：`webui/server.py:1263-1264`
- **问题**：`int()` 裸转、`read(length)` 不限量、服务器未设 `timeout`。
- **证据**：
  ```python
  length = int(self.headers.get("Content-Length") or 0)
  raw = self.rfile.read(length) if length else b"{}"
  ```
- **影响**：畸形头 `Content-Length: abc` 直接抛异常打断连接（无 400）；`-1` 会 `read` 到 EOF 挂住线程；大 body 无上限可吃到内存。
- **建议**：`try/except` → 400；`min(max(length,0), 4MB)`；`Handler.timeout = 30`。

## 三、低（4 条）

### 17. VPY 融合的备份是固定名 `.bak`，第二次覆盖第一次且失败静默
- **位置**：`core/vpy.py:333-340`
- **问题**：`path.with_name(path.name + ".bak")` 每次同名覆盖；`except OSError: pass`；主写非原子。
- **影响**：用户以为有回退点，其实第一次生成的版本已被冲掉；备份失败也没提示。
- **建议**：改用 `textio.backup()`（毫秒时间戳 + 防撞序号），失败写进 detail。

### 18. 「另存为自己的键位表」是两步写，第二步失败不回滚
- **位置**：`core/keys.py:331-368`
- **问题**：先写 `input-user.conf`，再改 `mpv.conf`；后者失败时前者已落盘，函数直接返回失败。
- **影响**：留下"文件已生成但 mpv 没指向它"的状态，下次升级 mpv-lazy 仍被覆盖——正是该功能要解决的痛点。
- **建议**：确认 `mpv.conf` 可写后再写目标文件，或失败时删掉刚生成的文件并在 detail 说明。

### 19. Big5 / GB18030 探测有歧义，猜错后会按错编码写回
- **位置**：`core/textio.py:84-96`
- **问题**：两种编码都能"干净解码"时按 `FALLBACKS` 顺序恒选 gb18030，`_score` 只数控制字符，无法区分。
- **影响**：纯 Big5 老配置被读成乱码，之后按 gb18030 写回（`lossy=False`，无警告）→ 乱码被固化。
- **建议**：把"两种都能解"标成 `uncertain`，随 `tf` 带出，`load_config_file` 的 warnings 提示用户确认编码。

### 20. `api_config_load` / `api_report` 的 `path` 没有路径白名单
- **位置**：`webui/server.py:438`、`690-696`
- **问题**：与 `api_raw_read:603` 不同，这两个接口直接 `Path(path)` 读取并回传全文。
- **影响**：任意路径读取。跨站 CSRF 读不到响应，但一旦页面存在 XSS 就是全盘任意读。
- **建议**：与 `api_raw_read` 统一走 `_inside(...)`，或限制到 `*.conf` / 2MB。

## 四、确认做得好的点（可直接引用）

1. **编码链路**：`core/textio.py:99-124` BOM→UTF-8→GB18030→Big5→有损兜底，且把 `encoding/bom/newline/lossy` 一起带出，写回时原样还原；`backup():162-180` 用毫秒时间戳 + 防撞序号，注释明确写了"秒级精度会让安全网失效"。
2. **宁可不动也不吃用户配置**：`core/writer.py:41-100` 的两条铁律（遇空行即收尾、认不出就 `ok=False` 整块不动），并有 `tests/test_writer.py:175` 钉住。
3. **读写对称的小节处理**：`writer._section_map`（236-254）与 `loader.parse_config_text` 都区分 `[profile]` 与全局区，杜绝"改全局 scale 却改了第一个小节"。
4. **最像事务的一段**：`core/dlcenter.py:274-395` archive 安装——tempfile 暂存 → 逐成员路径/白名单/黑名单/扩展名 → 文件数与体积上限 → 冲突整批判定 → 逐个备份 → 记 sha256 → `finally` 清暂存。
5. **校验不假通过**：`core/installer.py:277-291` 空 digest 返回 `False, actual`；`asset_digest()` 还校验 64 位 hex。
6. **路径防护用真 API**：`webui/server.py:548-572` `_inside` 用 `resolve()+relative_to()`，并在注释里否定了字符串前缀法；静态文件与写入都复用它（可惜白名单的**输入**没守住，见发现 2）。
7. **传输抽象干净**：`webui/stdio.py` 强制 `QUIET_STDOUT`、日志全走 stderr，用 `tests/test_stdio.py`「stdout 每一行必须能 json.loads」钉死；`webui/api.py` 的 `dispatch` 是纯函数、路由存属性名以解循环导入。
8. **Electron 基线正确**：`contextIsolation:true`、`nodeIntegration:false`、会话级 CSP（`connect-src 'none'`）、preload 只暴露一个 `__MPVCB_INVOKE__`。
9. **卸载的谨慎**：`core/dlcenter.py:646-699` 按记录哈希逐个校验，改过的不删、部分成功如实报数（"报一句已卸载然后偷偷留下三个文件比直接报错还糟"）。
