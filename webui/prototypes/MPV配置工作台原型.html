UI / UX 定稿草案

一套工作台，三种深度。

不是把九个页面做漂亮，而是把“我在改哪份配置、改了什么、会不会坏、怎么退”这四件事一直摆在眼前。下面是这套原型遵守的规则。

结构

三个面，不是九个页

功能不删，只换入口。

  • 接上配置：目标、可写状态、最近配置。
  • 调校：信号路径 + 选项 + 监视器。
  • 检查写入：差异、体检、备份、写入，收进监视器。
  • 快捷键、下载、体检不再占独立页面，改成抽屉和动作。
导航

导航是信号路径

按 mpv 真正处理画面的顺序排，不按功能清单排。

  • 解码 → 缩放 → Shader → 同步 → 音频 → 字幕 → 性能。
  • 每一段带一个计数，告诉你这里动了几项。
  • 切换段时，监视器只高亮这段产生的行。
深度

三档深度，两档密度

简化的是路径，不是能力。

  • 概览：每段 1–3 个关键决定，带一句“为什么”。
  • 调校：核心参数全展开，仍然分得清主次。
  • 全量：全部原生选项 + 自定义值，给真的知道自己要什么的人。
  • 密度只改行高和说明展开，不改功能。
状态

四个问题一直有答案

  • 我在改哪份？顶栏、左轨、状态条三处一致。
  • 改了什么？“改动胶片”每格可点，直接跳回那一项。
  • 会不会坏？监视器常驻“差异 / 体检”。
  • 怎么退？撤销、备份、写入前确认，都是主路径。
动效

只解释变化，不表演

所有动效都回答“刚才发生了什么”。

  • 切段：180ms 淡入 + 4px 位移，信号点滑到新段。
  • 改一项：对应配置行高亮 600ms，改动数跳一下。
  • 开监视器 / 说明：220ms 滑出，不弹跳。
  • 报错不抖，直接把那一行滚到眼前。
  • 尊重 reduced motion；关掉动效后信息不丢。
克制

不做这四件事

  • 不把每个区块做成圆角卡片。
  • 不用荧光绿、紫色渐变、玻璃拟态。
  • 不把等宽字体当装饰；它只服务 key 和配置。
  • 不做没有信息价值的 hover 浮起和视差。

视觉记忆点只留一个：监视器 + 信号路径。其余保持安静。
